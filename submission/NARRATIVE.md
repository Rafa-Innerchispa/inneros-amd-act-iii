# ACT III Narrative

## Core story

This project began with a deceptively simple experiment.

After gaining access to an AMD Radeon AI PRO R9700 and the ROCm ecosystem, we saw AMD Skills emerging as a way for coding agents to consume validated AMD workflows. The idea seemed almost trivial: connect Cursor, Codex and other agents to local ROCm compute, give them the right skills, and let them work together.

Then reality arrived.

The models could reason. The skills could teach workflows. The GPU could run serious local inference.

But the agents still did not form a reliable system.

Tasks became stuck between queues. Claims expired. Headless processes died. Evidence could be incomplete. Local AMD and Intel paths behaved differently. Owner approvals duplicated. An agent could finish code while the orchestration layer still believed the task was running.

Those failures became the roadmap.

InnerOS evolved into the missing execution layer between **human intent, skills, agents and AMD compute**.

Today the platform is moving toward a simple operating model:

**ChatGPT orchestrates → local AMD/Intel Dev Swarm executes first → Cursor/Codex/Antigravity become specialist lanes → the owner is interrupted only when a decision deserves human attention.**

ACT III shows that evolution through one real Intelligent Industry scenario: a smart-building infrastructure incident.

A degradation report enters InnerOS. Specialist agents correlate telemetry, retrieve topology and prior evidence, plan remediation and route work to local AMD ROCm execution. Any mutating action requires explicit approval. The final run produces structured evidence, runtime identity, hashes and Human Time Returned, then remains available for forensic replay.

The central claim is not that one agent became smarter.

It is that **AMD compute made local intelligence practical, AMD Skills showed how agents could gain hardware-aware capabilities, and the failures of connecting those pieces forced us to build the coordination fabric that became InnerOS.**

## Judge takeaway

**AMD did not merely accelerate our application. It changed its architecture.**

Without local AMD compute, InnerOS would be another cloud-first orchestration layer.

With it, local-first execution became the default design constraint and sovereign multi-agent operation became a realistic product goal.
